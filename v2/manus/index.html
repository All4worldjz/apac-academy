Manus 是什么 产品

一个通用 Agent：用户描述目标，它在一台云端虚拟机里规划、上网、写代码、生成文件，最后交付报告、网站或表格。

E2B 是什么 技术

为 Agent 提供云端沙箱的开源公司，底层是 AWS 开源的 Firecracker 微虚拟机：约 150 毫秒启动，每个用户一台，彼此隔离。

为什么值得研究 时机

发布八个月年化收入过 1 亿美元，2026 年中约 4 亿美元（财新报道）；同时经历了被收购、被叫停、回购独立的全过程。

读原典时会遇到的 11 个词

Sandbox沙箱

给 Agent 的隔离运行环境，用完即弃，出错时影响被限制在内部。

microVM微虚拟机

只保留必需设备的轻量虚拟机，有独立内核，启动以毫秒计。

FirecrackerFirecracker

AWS 开源的微虚拟机技术，基于 KVM，用 Rust 编写。

KVM内核虚拟机

Linux 内核自带的硬件虚拟化能力，是 Firecracker 的基础。

Container容器

共享宿主机内核的隔离方式，启动快但隔离弱于虚拟机。

gVisor / Kata其他强隔离方案

gVisor 用用户态内核拦截系统调用；Kata Containers 用轻量虚拟机运行容器。

KV-cache键值缓存

模型复用已计算过的上下文，命中率决定 Agent 的延迟与成本。

Context Engineering上下文工程

设计 Agent 读入什么、按什么顺序、怎样压缩和复用的工程方法。

Wide Research广域研究

多个 Manus 实例并行处理大批量对象的机制。

ARR / Run-rate年化收入 / 运行率

按当前月收入折算的年度收入；运行率可包含用量收入。

Manus 由蝴蝶效应公司（Butterfly Effect）开发。团队先做了 AI 浏览器插件 Monica，再在 2025 年 3 月推出通用 Agent 产品 Manus。

公司的核心判断：Agent 的能力不只取决于模型，更取决于给它一台什么样的电脑、怎样管理它的上下文。

肖弘 · 联合创始人兼 CEO

2022 年创办蝴蝶效应公司。先推出 Monica，一个整合多家大模型的浏览器插件，用于翻译、总结和写作。

Manus 技术路线的主要阐述者。2025 年 7 月发表《AI Agent 的上下文工程：构建 Manus 的经验》，是业内引用很多的一篇工程文章。

负责产品。在 E2B 的案例文章中解释了 Manus 为什么选择 E2B 沙箱，以及 Agent 需要的 27 种工具。

2025 年 7 月推出的并行机制：面对需要处理数百个对象的任务，多个通用 Manus 实例同时工作，再汇总结果。例如比较 Fortune 500 公司。

持续迭代

2025 年 10 月发布 1.5 版，公司称此后月增长超过 20%；2026 年上半年陆续接入 Canva、Zoom、Similarweb、Notion、Shopify 等应用。

为什么 Agent 需要一台自己的电脑

聊天机器人只输出文字；Agent 要动手：装软件、跑代码、打开网页、读写文件。这些代码由模型临时生成，谁也不能保证它安全。

代码不可信

模型写的代码可能有错，也可能被网页里的恶意指令诱导。必须假设它随时会做出意料之外的事。

用户要隔离

成千上万的用户同时运行任务，一个用户的 Agent 不能看到、也不能影响另一个用户的数据。

任务要持续

一个任务可能运行数小时，中途还要停下来等用户输入或完成人机验证，环境要能暂停、恢复、保存。

沙箱（Sandbox）就是给 Agent 一台「用完即弃、彼此隔离、随叫随到」的电脑。Manus 每个会话都运行在一台专属的云端虚拟机上，截至 2025 年 12 月累计创建了超过 8,000 万台。

打个比方：合租、独栋和酒店套房

三种隔离方式的差别，可以用住房来理解。

方式隔离边界启动速度适合的 Agent 场景
进程 / 容器共享宿主机内核，靠命名空间与权限隔离快运行可信的内部代码
传统虚拟机完整的硬件虚拟化慢长期运行的固定环境
Firecracker 微虚拟机基于 KVM 的硬件虚拟化，每台有独立内核，设备模型极简约 125 毫秒（Firecracker 官方数据）大量用户、运行不可信代码、按需创建和销毁

Firecracker 由 AWS 开发并开源，用 Rust 编写，最初用于支撑 Lambda 与 Fargate 这类无服务器服务。gVisor、Kata Containers 是另外两种常见的强隔离方案，思路不同，可在私有化部署时一并评估。

E2B：把微虚拟机做成 Agent 的云

E2B 是一家开源的 Agent 沙箱公司，底层使用 Firecracker 微虚拟机，开发者用几行代码就能为每个 Agent 创建一台云端电脑。

它提供什么

按需创建的云端沙箱：完整的 Linux 环境，可运行 Python、JavaScript、Bash，可安装软件包、使用浏览器和文件系统。每个用户一台，互不影响。

公司与规模

2025 年 7 月完成 2,100 万美元 A 轮（Insight Partners 领投），累计融资 3,200 万美元。公司称 88% 的财富 100 强企业已注册使用，客户包括 Hugging Face、Perplexity、Groq 和 Manus。

对企业 Agentic AI 的启示：沙箱就是安全边界

学院归纳。企业让 Agent 动手之前，沙箱这一层要先设计好。

部署前的检查清单

  • 隔离级别：运行模型生成的代码，优先选微虚拟机或同等强度的隔离。
  • 网络出口：默认禁止外网，按任务开白名单，防止数据外传。
  • 凭证管理：密钥不写进沙箱，由外部保管、按需短期授权。
  • 审计：记录每条命令、每次文件读写与网络访问。
  • 资源与时长：设置 CPU、内存、运行时长上限，防止失控任务。
  • 数据驻留：沙箱与持久化数据存放在合规的区域或客户自有环境。

在国内私有化环境里怎么做

  • 自建：E2B 与 Firecracker 都开源，可在客户机房基于 KVM 自建沙箱集群。
  • 选型：同时评估 Firecracker、gVisor、Kata Containers 的隔离强度、启动速度与运维成本。
  • 适配：确认在国产服务器与操作系统上的虚拟化支持情况。
  • 与业务系统的接口：沙箱只拿完成任务所需的最小数据，结果通过受控接口写回。
  • 分级：只读查询、内部代码执行、访问外网、写回业务系统，按风险分级审批。

上下文工程：Manus 的六条经验

来自季逸超 2025 年 7 月的文章。团队四次重写 Agent 框架，总结出这些做法。

输入与输出 token 比约 100 : 1Agent 每一步都要读入完整上下文
缓存与非缓存的价格差10 倍以 Claude Sonnet 为例：0.30 对 3 美元 / 百万 token
一个典型任务约 50 次工具调用
框架重写4 次团队自述
1 围绕 KV 缓存设计

保持提示词前缀稳定、上下文只追加不修改、序列化顺序固定。缓存命中率直接决定延迟和成本。

2 屏蔽工具，而不是删除

任务中途增删工具会让缓存失效、让模型困惑。做法是在解码时屏蔽暂不可用的动作，并给工具统一的名称前缀，如 browser_、shell_。

3 文件系统就是上下文

把信息写进沙箱里的文件，相当于无限、持久的记忆。压缩时只保留网址或文件路径，需要时再读回，信息不会永久丢失。

4 用 todo.md 复述目标

长任务里反复改写待办清单，把总体计划推到模型最近的注意力范围里，减少跑题。

5 把错误留在上下文里

失败的动作和报错信息不要清除，模型看到后会调整判断、避免重犯。作者认为错误恢复能力是衡量 Agent 的重要指标。

6 避免少样本陷阱

上下文里重复的动作模式会让 Agent 机械模仿，例如批量审阅 20 份材料时。适度引入格式和措辞的变化。

上下文工程与沙箱是一体的

学院分析。第三条「文件系统就是上下文」只有在 Agent 拥有一台持久电脑时才成立。

  1. 沙箱提供记忆：文件写在沙箱里，任务暂停、恢复后仍在
  2. 沙箱提供行动：浏览器、终端、文件三类工具都在沙箱里执行
  3. 沙箱提供边界：出错或被诱导时，影响被限制在这台一次性电脑里
  4. 沙箱影响成本：启动速度与资源开销决定了能否为每个用户、每个子任务各开一台（Wide Research 依赖这一点）

护城河与风险

学院分析。

护城河

  • 工程积累：上下文工程与沙箱编排的经验，难以快速复制。
  • 迭代速度：不训练基础模型，模型进步直接变成产品进步。
  • 交付物导向：用户为「做完的工作」付费，而不是为对话付费。

风险

  • 模型依赖：依赖第三方模型，模型公司自己做 Agent 时会正面竞争。
  • 算力成本：每个任务都要开一台虚拟机、读入大量上下文，毛利受成本影响。
  • 监管与股权：跨境收购被叫停后，股权结构、数据与市场准入仍有不确定性。
  • 企业化：从个人与专业用户走向企业客户，需要补齐权限、审计与私有化能力。

对跨境 AI 公司的启示

学院分析，不构成法律意见。

  1. 注册地不等于审查边界：团队、技术与数据的来源同样会被纳入审查考量
  2. 双向合规：美元基金投资可能受美国对外投资规则约束，境外收购也可能触发中国的外商投资安全审查
