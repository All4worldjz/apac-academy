01服务超百万开发者：张路宇谈再创业、中间层与全球化华创派 / 腾讯新闻 · 2024-06 · 中文 · 长访谈必读✓

原题：华创派｜Dify 张路宇：服务超百万开发者，再创业做大模型中间层

概述

迄今最完整的个人长访谈。他讲了从 12 岁做网站、初中离校，到蜗牛、飞蛾、CODING 和腾讯的经历；解释了为什么在模型、中间层、应用三层里选中间层，为什么开源、为什么叫全球化而不是出海。他还提出团队高于产品，北极星是真正投产的用户数。

精读笔记
  • 1991 年生，12 岁做个人站长，2003 年初中毕业后没有再上学；2009 年到苏州，第一份工作在蜗牛游戏，一进公司就带 20 人技术团队
  • 2018 年 7 月创办开发者测试协作 SaaS「飞蛾」，同年 12 月被 CODING 收购；收入表现让他认为国内 SaaS 市场离理想很远。此后在 CODING 近 4 年，负责超过三分之一的 DevOps 产品线并带 60 多人团队，随 CODING 并入腾讯
  • 创业三种动机：不满意现状、创造的欲望、利他主义，他认为利他主义最强
  • 在模型、中间层、应用三层里选中间层：模型层重投入且回报不确定，应用层是涌现式的、成功率低；中间层既有自身强烈需求，又有多年企业服务经验
  • To B 工具不为用户创造需求，只帮用户更快划掉待办清单上的一项；产品经理的核心职能是从无数需求里抽象出最大公约数
  • ChatBot 是过渡态：一个普通用户日常用的 Bot 不超过三个。第一版产品是 iMac 的「把手」，让用户觉得大模型可以亲近；之后主力是 Workflow
  • 开源五条理由：社区红利、全球贡献者、中间件需要中立可控、降低全球化门槛、品类需要最快渗透；「开源也是一种市场补贴」
  • 用「全球化」而不是「出海」：中国是全球的一部分，不会有中国版和海外版。日本网友质疑公司背景时，团队第一时间公开说明并开线上见面会
  • 北极星指标是基于 Dify 投产的用户数；Star 与收入是虚荣指标。当时 40 万安装里真正投产的「也许不到 5%」
  • 团队高于产品；招聘有意反大厂：「大厂只能模仿我们的产品，模仿不了我们的基因和做事方式」
关键原话
中国是全球的一部分
我们开源也是一种市场补贴
大家低估了中间件的工程难度
我最拿得出手的产品是我们的团队
观察要点

这是你理解他的「操作系统源代码」。开源五条理由、拒绝双版本、最大公约数这几个观点，几乎决定了他会怎样看待区域市场的打法。

03Dify 从被低估到成为明星项目，到底做对了什么42章经 播客 / 腾讯新闻 · 2025-12 · 中文 · 播客对谈必读✓

原题：Dify从被低估到成为明星项目，到底做对了什么｜对谈 Dify 创始人路宇

概述

他把成功归结为「耐心」，坚持 Day 1 定下的开源、To B、全球化三条策略。他认为 Workflow 会长期存在，因为人类生产需要可预测性；未来是神经网络负责联想、符号系统负责逻辑判断。智力会变成对称资源，竞争力来自非对称的上下文与判断。他也逐一点评了 LangChain、Coze、n8n 和 OpenAI 的 Agent 工具。

精读笔记
  • 成功归结为两个字：耐心。Day 1 定下开源、To B、全球化三条策略，并衍生出开放生态、模型中立、工程优先
  • 三波市场：2023 年胜在界面友好；2024 年 Workflow 与插件生态，第一批付费企业进场；2025 年模型明显进步，开源与多模态成熟
  • 用户光谱：LangChain 与 AgentKit 偏硬核工程师，n8n 比 Dify 稍偏左，Dify 在中间并向弱技术用户延伸，Coze 更偏右但生产属性不足
  • 逐一点评竞品：GPTs 没想清楚 Bot 该由谁做；Coze 发布时他焦虑了 48 小时；n8n 起步更早、生态更完善；AgentKit 短期不构成实质威胁，客观上帮行业做了市场教育
  • 模型像一条鱼，放进 IDE 长成 Cursor，放进沙盒长成 Manus，放进企业上下文就长成 Dify
  • 大家低估了工程：节点颗粒度这类决策有成百上千个，正是这些看不见的苦工构成产品的厚度
  • Workflow 会长期存在，因为人类生产需要高度可预测性；完全智能化可能还要三到五年
  • 技术世界观：Transformer 不能解决所有问题，未来是神经网络负责联想、符号系统负责逻辑判断
  • 「SaaS 会变快时尚」只对了一半：数据结构这类不变的基础仍需人来定义
  • 客户已在编排四五百个节点的 Workflow；安克搭建了上千个工作流，把 Agent 当作新的生产资产管理
  • 创始人必须快乐：不喜欢 996，也反对机械的 8 小时制
关键原话
长话短说，就是两个字：耐心
Workflow 会长期存在
Dify 从来没有被谁杀死过
创业者的使命，是把未来带到现在
观察要点

Workflow 会长期存在、工程最值钱、模型趋同后比拼非对称的上下文与判断，这几条核心判断都出自这一篇。竞品点评是理解其竞争观的一手材料。

精读笔记

术语速查

读原典时会遇到的 26 个词

LLM大语言模型

GPT、Claude、DeepSeek 这类用海量文本训练出的模型，是这一切应用的发动机。它擅长理解与生成语言，但本身不会「做事」，需要被编排进流程才能干活。

Prompt提示词

写给模型的指令。同一个模型，提示词不同，结果天差地别。Dify 团队自嘲：写 Prompt 的人不叫工程师，叫「Prompt 艺术家」。

Token词元

模型处理文本的最小单位，也是计费单位。大致 1 个汉字 ≈ 1–2 个 Token。谈模型成本、上下文长度都离不开它。

RAG检索增强生成

先从你的资料库里查出相关内容，再让模型据此回答，专治「模型不知道你公司内部的事」。张路宇的提醒：数据不一定要多，但一定要好。

Embedding向量化

把文字变成一串数字（向量），语义相近的文字向量也相近，机器因此能「按意思」搜索。张路宇判断：未来所有数据都会被向量化一遍。

Fine-tuning微调

用专门数据继续训练模型，让它更懂某个领域。与 RAG 互补：微调改模型的「脑子」，RAG 给模型「查资料」的能力。

Agent智能体

不只聊天，还能自己拆解任务、调用工具、多步执行并检查结果的 AI 程序。2026 年 8 月起，Agent 在 Dify 里成为可独立维护、跨应用复用的一等资源。

Agentic Workflow智能体工作流

Agent 负责动态判断，Workflow 负责流程骨架：何时运行、谁来审批、结果去哪。这是 Dify 的核心叙事，也是本轮融资的主打方向。

Workflow工作流 / 编排

Dify 的核心形态：在可视化画布上把 LLM、工具、代码、条件分支连成一条流水线，每个节点可单独测试。张路宇打赌：未来的编程，编的就是 flow。

DSL领域特定语言

Dify 的 Workflow 可以导出成 DSL 文件、再导入别的工作区。张路宇称它是「最酷的功能之一」，也是他想建立的技术标准——就像 Docker 之于容器。

LLMOps中间层 / 大模型应用运维

夹在「模型」与「应用」之间的一层：负责编排、数据接入、提示词管理、评估与运维——Dify 所在的位置。2023 年初他们提出这个词时，全球几乎搜不到。

MCP模型上下文协议

让 AI 应用以统一方式连接外部工具与数据源的开放协议，相当于 AI 世界的 USB-C 接口。Dify 的 Agent 可以直接接入 MCP server。

AGENTS.MD给 AI 的项目说明书

放在代码仓库根目录的 Markdown 文件，写给 AI 编程代理看。在《分与合》里，张路宇把它当作约束 AI 行为的「单一事实来源」。

开源Open Source / OSS

源代码公开、人人可用可改。Dify 第一天就 99% 开源；张路宇视开源为一种「市场补贴」——用它换全球渗透率与企业信任。

PLG产品驱动增长

不靠销售大军，靠产品本身的口碑和免费使用带来增长，再向其中的企业用户收费。张路宇说 Dify 是一家「PLG toB 公司」：从创立到 2024 年 12 月，市场费用不到 40 万元人民币。

SaaS云订阅软件

开箱即用、按月订阅的在线软件——对应 Dify Cloud。它的相对概念是「自托管」。

自托管私有化部署 / VPC

把软件装进客户自己的服务器或 VPC，数据不出内网。中国政企与金融客户的硬需求，也是 Dify 企业版的主打能力。

SSO·RBAC·SCIM企业权限三件套

单点登录、按角色分配权限、自动同步员工账号开通与关闭。大客户采购清单上的常客。

SLA服务等级协议

对可用性与响应时间的合同承诺。Dify 企业版的 SLA 由合作伙伴协商提供——这正是渠道体系的价值位。

SOC 2 / ISO 27001安全合规认证

两项国际安全合规标准，大客户采购的入场券。Dify 已连续两年通过 SOC 2 Type II 与 ISO 27001，并符合 GDPR。

Pre-A 轮融资阶段

介于天使轮与 A 轮之间的一轮融资。Dify 本轮 3000 万美元，红杉中国（HSG）领投；媒体报道投后估值约 1.8 亿美元。

北极星指标North Star Metric

团队唯一最重要的那个数字。Dify 的不是 Star 数，而是「用 Dify 真正投产并赚到钱、获得 PMF（产品市场匹配）的用户数」。

状态基础设施SIG · State Infrastructure Gap

张路宇理论长文的核心概念：我们缺少一层记录「现实世界某对象现在处于什么状态」的基础设施，大量白领工作因此变成手工的「状态同步」。

控制论Cybernetics / Harness Engineering

研究「系统如何根据反馈自我纠偏」的学科（维纳，1948）。张路宇认为 AI 时代的工程师必须掌握它，把流水线设计成能自我纠偏的反馈闭环。

数字孪生Digital Twin

给现实对象建一个实时同步的数字副本。状态长文借用它说明「状态基础设施」应该长什么样。

Goodhart 定律古德哈特定律

「一项指标一旦成为目标，它就不再是好指标。」状态长文提醒：团队若只优化可量化的东西，就会偏离真实目标。

一个从自己的痛点里找基础设施缺口的人

工程师出身、自学成型的产品型创始人：习惯从自身的工作摩擦出发，把它抽象成一类基础设施问题，再用开源和全球化的方式交给更多人；他把团队和组织方式看得比单个产品更重。

自我生成型路径

1991 年生，12 岁开始做个人网站和社区，很早以独立开发者起步，编程与产品能力主要靠自学。他在访谈中把这段经历视为自己与同龄人的一个差异。

从痛点到基础设施

Dify 起点是他自己需要这样的工具；2026 年《State Infrastructure》又把会议、表格、审批归结为缺失的状态基础设施。两次推理路径一致：个人摩擦 → 共性结构 → 基础设施。

抽象与排序

他定义产品经理的核心能力是从大量需求中抽象最大公约数并排优先级，由用户驱动加数据驱动；团队内部设四条研究线，每周产出市场情报。

工程主义

认为中间件的工程难度被严重低估。他理解的工程是大量复杂因素的排列组合与最优化；硬科技本质上也是工程，只是尺度不同。

全球主义

用"全球化"而不用"出海"；技术工具天然无国界，只在中国成功不算真正成功；中国是全球的一部分，不做名称不同的中国版与海外版。

组织实验者

把团队放在产品之上；自认擅长精细化管理但刻意抑制；用"短跑速度跑马拉松"形容 AI 创业；招聘有意反大厂。

务实的理想主义

北极星不是 Star 或收入，而是真正投产并产生价值的用户数；2024 年他估计 40 万安装里严肃生产应用不到 5%。

理论化倾向（2026）

近期长文引用信息经济学、知识管理与控制论，并主动声明框架尚未经实证。思考对象从软件产品上移到组织如何工作。

坦诚直接

日本社媒质疑公司背景时，团队快速说明团队构成并开 Discord 直播回应。官方价值观第一条是 Simple & Sincere。

原声补遗：他怎么讲自己

以下内容来自他的长访谈、播客与专访。每一条都对应他做判断时的一个习惯。

三种创业动机

不满意现状、创造的欲望、利他主义。他自己的排序是利他主义最强：想做同事的「伯乐」，也希望用户解决问题时用的是世界上最好的产品。

「被迫一路向上」

技术管理不好就去做技术管理，产品方向不对就去做产品，公司战略有问题就做 CEO。驱动力是非常在意做的事有没有价值，不是头衔。

机会来自非对称信息

公开领域很难拿到，但在微观领域无处不在：你的心智、身边的人、你服务的对象。钻进一群人中间持续交流，是他认为获取非对称信息的最佳方式。

先上线，再说服

第一份工作时，只要判断产品有价值，他会绕过流程先把它上线，他自己称之为「先上线」。这解释了他为什么不喜欢没有理由存在的流程。

警惕被自己的故事说服

融资期一周见 30 个投资人、讲 30 遍同样的话。他的提醒是：拿到钱以后要回到第一性原理重新审视，不要基于自证预言做产品。

创始人必须快乐

他认为「CEO 就该吃苦扛压」是错的：人在巨大压力下想不清楚问题。他不喜欢 996，也反对机械的 8 小时制，因为心流本身就会让人忘记时间。「创业者的使命，是把未来带到现在。」

技术哲学：智能是什么，人在哪里

神经 + 符号

他认为未来的方向是神经网络负责联想与展开，符号系统负责逻辑与判断。依据是人脑能耗很低却高度智能，可能内置了帮助快速分类、建立因果的符号式结构。

智力会变成对称资源

模型能力会趋同，竞争力因此来自非对称的部分：上下文、判断和流程。他关心 Dify 能否保留个体与组织的这些非对称能力，帮用户从六十分走到八十分。

鱼缸比喻

同一个模型放进不同的上下文，会长成不同的产品：放进 IDE 是 Cursor，放进沙盒是 Manus，放进企业是 Dify。上下文决定产品形态。

人是传感器，平台是藏宝图

模型的可信度已从六七成升到九成以上，但用好它要找到「密码」，这取决于认知框架和提问能力。人是模型理解现实的传感器，Dify 提前设计好找到答案的路径。

数字存疑，方向可信

他认为大模型给出的具体数字不可全信，方向往往可靠；用 AI 辅助设计时必须提供足够的背景信息。

技术平权

Agent 与开源模型让个体工程师有机会与大公司抗衡；他判断非开发者广泛参与构建可能在两三年内发生。

产品方法论补充

节点颗粒度

节点太细就像写代码，一般人用不起来；太粗则能力不够。他说这样的决策有成百上千个，共同构成产品的厚度。只靠 AI 生成代码、轻视工程的产品是「薄」的。

插座式设计

企业不敢把技术栈绑在一家模型上，所以模型要能热插拔，原生能力与自定义扩展互不干扰，并且向后兼容。

最标准的场景就是不标准

用得最好的客户几乎都按自身需求定制，Dify 是连接各类流程与能力的胶水。安克搭建了上千个 workflow、上万个原子能力，把 Agent 当作与人力并列的生产资产。

只有流程可以复用

做出好产品有四种路径：硬科技、创造力、稀缺壁垒、完整流程。前三者难以复用，只有流程可以。这是 Workflow 的哲学根基。

SaaS 不会消失

「快时尚式」自建只对了一半。数据结构等不变的部分仍要人来定义；未来的范式是人定义结果与结构，AI 负责个性化定制。

商业化有时滞

从新技术出现到 B 端付费，通常要半年到一年。这决定了 APAC 的收入预期不能按社区热度线性外推。

New Dify Agent（2026 年 8 月发布）

从节点到一等资源

2025 年的 Agent 节点被绑在出生的那条 Workflow 里，换个地方就要重建。New Agent 有自己的模型、Prompt 与工具配置，一处维护、多处复用，可发布为 Web 应用、开放 API，或放进多条 Workflow。

Build · Manage · Track

Build：用对话起草配置，改动先进入草稿，Agent 同时维护一份 build_note.md 记录配置过程；Manage：一个共享 Agent 取代所有拷贝；Track：单次运行的完整链路追踪加长期行为监控。

Tools · Skills · CLI

Tools 是受管理的集成（Marketplace、自定义 API、MCP、把 Workflow 包装成工具）；Skills 把指令、参考资料与脚本打包成可复用方法；CLI 在沙盒里一次性安装运行。反复出现的 CLI 用法沉淀为 Skill，需要跨 Agent 稳定时再升级为共享能力。

修复哲学：Agent 出错时，要问的不是「怎么修好这个回答」，而是「这个修复应该落在哪里」。官方举的例子是一个把两款产品营养成分混在一起的产品对比 Agent：往 Prompt 里加一条指令只能修好这一次；把产品信息拆成独立记录、更新 Skill 让它先检索再核对证据，才会改进此后的每一次运行。一句话分工：Agent 负责任务内的动态判断；Workflow 负责何时运行、前后检查、审批与输出去向。

通用概念：文档解析与 OCR、分块（大小、重叠、父子块）、向量嵌入、近似最近邻索引（如 HNSW）、关键词检索（BM25）、混合检索、重排序（cross-encoder）、召回率与精确率、上下文窗口与「中间遗忘」。

Dify 对应：高质量索引用嵌入模型，经济索引用每块约 10 个关键词、不耗 token，且高质量建好后不能退回经济；检索方式有向量、全文、混合三种，混合检索可设语义与关键词权重或接重排模型；TopK 默认 3、分数阈值默认 0.5；父子分块用小块精准匹配、返回大块作上下文，仅支持高质量索引；Knowledge Pipeline 把连接、解析清洗分块嵌入、存储三层做成可替换插件。

Dify 对应：模型中立、可热插拔，模型以插件形式提供；插件共六类：模型、工具、Agent 策略、扩展、数据源、触发器。

售前诊断：客户说「RAG 回答不准」时的排查顺序
  1. 先看数据：文档是否解析正确（表格、扫描件、页眉页脚），这一步的错误后面无法弥补。
  2. 再看分块：块太大稀释语义，太小丢失上下文；长结构化文档考虑父子分块。
  3. 再看召回：正确片段有没有被检索出来？专有名词多时用混合检索，必要时加重排。
  4. 再看提示与编排：是否要求只依据检索内容作答、是否引用来源、是否需要问题分类分流。
  5. 最后才换模型：换更大的模型通常最贵，也最容易掩盖前面的根因。

这与 New Agent 文档的原则「修复应该落在哪里」，以及张路宇「追问到根因」的价值观一致。

技术对话中最容易说错的五件事
  • 把 RAG 和微调当成二选一。实际上微调多用于改变风格或格式，RAG 解决知识时效与可追溯。
  • 说「有了 MCP 就不需要平台」。MCP 解决接入标准化，不解决编排、治理与评估。
  • 承诺「Agent 能自主完成整个流程」。受监管场景需要确定性流程和人工审批节点。
  • 用 GitHub Star 证明企业级能力。客户要看的是 SSO、RBAC、审计、私有化与 SLA。
  • 把「经济索引」当作省钱首选。它只支持关键词检索，准确性较低，适合预算极紧或纯关键词场景。

中国卖的不是「Dify」，而是企业统一的 Agentic 应用层

中国不只是又一个销售区域，而是 Dify 企业版 PMF 最严苛的压力测试场：大厂免费、开源竞品许可宽松、信创与私有化门槛高、项目化诱惑大。本节综合了公开资料与学院的分析建议，每条都标注了证据等级。

核心判断

在中国要赢的是「中立、可控、可私有化的企业 Agentic 应用层」这个品类心智，而不是「中国版低代码 AI 平台」。

最危险的一种成功：签了很多大项目、收入涨得很快，但自有交付团队同步膨胀，核心产品被本地功能需求拖走。这是商业上成功、平台上失败。

已能确认的中国相关事实
  • 上海办公室的职能是 APAC 市场进入与企业销售，不只是中国办公室
  • 阿里云 DMS 与 Dify 官方合作提供托管的 Dify 企业版：DMS 收托管费，企业版许可证向 Dify 官方单独购买；支持多租户、SSO、审计、品牌定制，可把自建实例迁入
  • 中文企业版定价页设有中国大陆客服电话；协商 SLA、定制集成、1 对 1 培训由合作伙伴提供
  • 媒体称 Dify 为国内使用量第一的开源智能体开发平台，并把它归入「开源框架型」路线
  • 中国伙伴页列有覆盖金融、医药、零售、制造、央国企的钻石伙伴
PMF 证据阶梯
Tool PMF开发者觉得比自己写快，社区版大量安装风险：只是开发者工具
Production PMFCIO 和安全团队敢让它跑生产：私有化、审计、权限、高可用证据：生产流量、企业版转化
Platform PMF从 1 个团队扩到多个 BU，应用和能力在组织内复用证据：第二个 BU 上线时间、NRR
Economic PMF交付不靠 Dify 自己堆人，伙伴与平台能力承担规模化证据：收入 / 服务人数、伙伴贡献 ARR

正确的终局：客户不再问「Dify 能做哪个场景」，而是问「哪些 AI 场景应该放到 Dify 平台上」。反方校验：如果客户第二年没有新增 BU 或应用，说明还停留在 Tool PMF。

中国伙伴生态：现成的骨架

官方伙伴计划已经把角色分好了。中国 GTM 的第一步不是重建渠道，而是把这套骨架用满。

经销商

做商业咨询或专业服务的机构，通过转售 Dify 企业版获得利润。

服务伙伴

IT 服务商、系统集成商与 ISV。除转售外，可以自主定价提供技术服务与培训，并联合销售向量数据库、云用量、定制模型等产品。

Marketplace 伙伴

拥有知识产权或合法授权的公司与开发者，把应用和插件上架 Dify Marketplace 并变现。

  • 加入免费，产品与许可证费用按标准方案计收
  • 申请后通常五个工作日内答复，入口在伙伴页或 business@dify.ai

  • 分层经营：钻石伙伴承接政企与大客户私有化交付，金牌伙伴按行业铺开，原厂只做授权、产品与关键客户
  • 交付不进原厂：企业版 SLA 本就由伙伴提供，原厂扩张交付团队等于和自己的伙伴竞争
  • Marketplace 是第二条收入线：引导伙伴把行业插件与模板上架，让伙伴的知识产权沉淀在平台上
  • 竞合要有边界：阿里云既是战略伙伴、也提供 Dify 托管服务，同时在做自己的 Agent 平台；合作口径需要与总部统一

中国、日本、澳新之外：先看证据强度，再决定投入

不把「这个国家 AI 采用率高」等同于「Dify 在这里有 PMF」。每个市场都标注了 Dify 专属公开信号的强度，证据弱的只给验证性策略。港澳台是否归属中国区由区域划分决定，这里先单列。

印度Tier 1 · 规模

证据强度：高
