01对话景鲲：AI 产品的 All in One，是上下文的 All in One虎嗅 · 2026-08 · 中文 · 长访谈必读✓

原题：对话Genspark景鲲：AI产品的All in One，是上下文的All in One

概述

景鲲迄今最完整的中文长访谈。他解释了为什么关掉上线十个月的 AI 搜索、为什么 Claude Sonnet 3.7 是转折点、All in One 的真正含义，以及对模型成本、开源闭源、AI 创业存活率的判断，还列出了公司的核心市场。

精读笔记
  • 关掉搜索的理由：用户不是为了搜索而搜索，而是为了把事办完；搜索用户成了 Super Agent 的入口
  • Claude Sonnet 3.7 让他确信模型已经能自己决定何时调用工具、何时停下，全流程 Agent 从此可行
  • All in One 不是功能堆叠：先是模型一体化，再把散落在各工具里的工作上下文汇聚起来；上下文越完整，AI 越懂用户，成本也越低
  • 用渔业公司、寿司店和批发商比喻模型实验室、应用公司与模型分发平台的分工，认为价值在应用层
  • 判断两年内同等能力模型的使用成本会降到现在的 1%；企业市场正在从堆 token 转向 token 优化；开源与闭源会走向融合
  • AI 应用公司有机会成长为万亿美元规模，但创业公司绝大多数会死
  • 长期愿景是 Work does itself：用户每天只需确认通过或打回修改
  • 招人看心态年龄、开放度、自驱力和行动力，不看生理年龄；团队是自家产品的首批用户
  • 伟大的产品承认差异，但要把差异抽象化；分发本身就是壁垒
  • 列出的核心市场：美国、韩国、日本、法国、印度、巴西
关键原话
上下文的 All in One
分发本身就是壁垒
Work does itself
观察要点

这是理解 Genspark 决策逻辑的「源代码」。核心市场名单里没有中国，也没有东南亚和澳新：这既划定了大中华区的边界，也说明亚太负责人需要自己争取资源。

02Anthropic 客户案例：Super Agent 用 Claude 调度 150 多个工具Anthropic · 2026 · 英文 · 客户案例必读✓

原题：Genspark's Super Agent orchestrates 150+ tools with Claude

概述

Anthropic 发布的客户案例，主要采访朱凯华。讲清了 Super Agent 的架构演进：从僵硬的有向图到 ReAct 式循环，多模型并行规划，以及约 50 名工程师用 AI 写出全部代码的工程方式。

精读笔记
  • 最初的 Agent 设计是由预定义节点组成的有向图，被认为太僵硬后推翻重写
  • 重写后采用 ReAct 式循环：模型决定调用哪个工具、何时补充信息、何时回退、何时总结返回
  • 复杂规划任务并行请求多个前沿模型，再由一个模型合并方案
  • 约 50 名工程师通过 AI 工具产出全部代码，部分人运行从 issue 到测试的自动化流水线
  • 新功能几乎每周上线
  • 目标是把软件工程师用 Claude Code 的体验带给所有白领
关键原话
The moat is execution speed
观察要点

做售前和前线部署的同事要能讲清这套架构；「护城河是执行速度」是和创始团队对话时最该准确引用的一句话。

04朱凯华 AI Dev 25 演讲：Genspark 怎样造出 Super AgentSummify（演讲摘要） · 2025 · 英文 · 演讲摘要✓

原题：AI Dev 25 x NYC: Kay Zhu, How Genspark built a Super Agent

概述

第三方整理的朱凯华演讲摘要。核心思路被概括为「少控制，多给工具」，并给出提示缓存、上下文压缩、校验器等降本提效手段。

精读笔记
  • 固定工作流遇到边缘情况会断，错误逐步累积
  • 给 Agent 完整的环境和工具，而不是严格限定步骤
  • 只追加不改写的上下文设计，提示缓存命中率 80% 以上
  • 上下文压缩与隔离；校验器与结果双重核算
  • 保留人工检查点
  • 使命目标：让十亿知识工作者实现每周三天工作
观察要点

作为思路引用，不当作逐字原话。技术讨论中能讲出缓存命中率和上下文设计，才算真正理解这套架构，而不只是会讲「多模型」。

他们怎么讲自己

以下观点来自两位创始人的公开访谈、演讲和合作方案例。

话题他们的说法对区域业务的意义
为什么关掉搜索用户要的是结果而不是链接。景鲲把愿景概括为「你只需要设定目标，我们交付做完的工作」，以及从「管理任务」变成「驱动结果」给客户讲的是交付物和省下的工时，不是 AI 功能清单
护城河是什么朱凯华：「护城河是执行速度。」景鲲：分发本身就是壁垒，企业级分销能力「已经非常有价值」区域负责人的价值就是分发：伙伴、渠道、市场速度
All in One一体化的核心是上下文的一体化，不是功能堆叠：先是模型一体化，再是把散落在各工具里的工作上下文汇聚起来企业销售要讲连接器、记忆与数据治理，而不只是 Slides 和 Sheets
长期愿景Work does itself：AI 承接重复事务，人只做判断，理想状态是用户每天只需确认通过或打回修改；朱凯华的说法是让十亿知识工作者实现每周三天工作叙事要落到「人做判断、Agent 做执行」的岗位改造
全球化核心市场包括美国、韩国、日本、法国、印度和巴西；「伟大的产品承认差异，但要把差异抽象化」区域需求要抽象成全球功能，不要求做区域分叉版本
对行业的判断模型会同质化、商品化，价值向应用层转移；两年内同等能力模型的成本将降到现在的 1%；AI 应用公司有机会做到万亿美元，但 99% 的创业公司会死他相信应用层，也极度清醒，适合用数据和速度说服他

少一点控制，多一点工具

Genspark 的技术路线和 Dify 截然相反：不把流程画成固定的图，而是让模型在循环里自己决定下一步。

从工作流图到 Agent 循环

最初的设计是由预定义节点组成的有向图，团队认为「太僵硬」。重写后的 Super Agent 采用 ReAct 式循环：模型自己决定调用哪个工具、何时补充信息、何时回退、何时收尾。朱凯华的原话是：「如果模型足够强，它应该知道什么时候调用哪个工具、什么时候停下。」

固定流程是脆弱的

在他的演讲里，固定工作流遇到边缘情况就会断，错误还会层层累积；Agent 应该观察、调整计划、从错误中恢复，更接近人解决问题的方式。转折点是 2025 年初测试 Claude Sonnet 3.7：它「知道什么时候停，也知道该调用哪些工具」。

多模型协作，模型无关

不同前沿模型做不同的事；复杂规划会并行请求多个模型，再由一个模型合并方案。模型数量从 2025 年 4 月的 8 个增加到 2026 年的 70 多个；大部分任务用便宜模型，关键决策用高端模型。

工程细节决定成本

只追加不改写的上下文设计让提示缓存命中率保持在 80% 以上；配合上下文压缩与隔离、结果校验器和用户反馈驱动的迭代。这些是毛利率的来源。

产品矩阵：一个工作空间，交付成品

定位是面向知识工作者的 AI 工作空间：用户给出目标，拿回可以直接用的文件、网站或应用。

产品做什么销售时怎么讲
Super Agent通用 Agent，调度 150 多个工具与 70 多个模型完成多步任务所有能力的入口，演示用它从一句话做出完整交付物
AI Slides / Sheets / Docs生成可编辑的演示文稿、财务模型和客户文档最容易量化的场景：报告、提案、董事会材料的工时下降
AI Developer / AI Design用自然语言生成全栈网页、移动应用、海报与品牌素材市场、运营团队的自助交付能力
Call For Me基于实时语音接口的电话代理，由一个影子模型监听通话质量在日本因「代打辞职电话」走红，展示了消费者侧的病毒传播力
GenMail · GenTeam在 Gmail、Outlook 里起草回复和跟进；人与不同角色的 Agent 在共享空间协作团队席位扩张的抓手

AI Workspace 6.0 的 Agentic Engine 由四步组成：路由（Routing）、评估（Evaluation）、编排（Orchestration）、自我进化（Self-Evolving），调度 70 多个模型、150 多个工具和 20 多个付费数据集。主要版本大约每两个月发布一次。

企业版：从个人效率工具到团队席位

Genspark for Business 于 2025 年 11 月推出，是亚太企业销售的主战场。

定价
  • Team：每席位每月 30 美元，含 70 多个模型、每席位每月 1 万额度、60GB 存储、集中管理与账单
  • Enterprise：定制报价，官网称通常为年费六位数美元，年合同不限席位；每席位每月 2 万额度、额度池、模型治理
  • Custom：在 Genspark 基础设施上构建 AI 功能的定制方案
安全与部署
  • SOC 2 与 ISO 27001；承诺不用客户数据训练基础模型
  • SAML 单点登录与 SCIM（Okta、Entra ID、Google Workspace）、RBAC、审计日志、客户自管密钥
  • 可在美国、欧盟或亚太区域部署；面向受监管行业提供 VPC 对等连接和私有网络
  • 200 多个连接器，支持 MCP；可把内部 API 封装成无代码技能

和 Dify 的关键区别：Genspark 是闭源的 SaaS 工作空间，按席位收费，价值主张是「交付成品」；官网列出的是美国、欧盟、亚太的区域云部署和 VPC 私有网络，没有列出客户机房内的私有化部署。这决定了它在政府、金融等强监管客户面前的打法：靠区域数据驻留、本地伙伴和合规认证，而不是私有化交付。

极小的团队，极快的节奏

Genspark 用几十人的团队做到了 2.5 亿美元年化收入。理解它的组织方式，是理解区域业务怎么做的第一步。

人少

Super Agent 爆发时团队约 20 人（OpenAI 案例）；2026 年 Anthropic 案例称约 50 名工程师。日本分析文章估算全员约 70 人，并引用 CTO 不打算超过 100 人的说法，官方未公开确认。

AI 写代码

工程师通过 AI 工具产出全部代码；朱凯华用 Claude Code 做规划，部分工程师跑着从 issue、PR、评审、合并到测试的自动化流水线。GenOffice 由一名工程师在 7 天内完成。

发布即节奏

10 周发布 8 个产品；新功能几乎每周上线；工作空间大版本约两个月一次。朱凯华：「护城河是执行速度。」

先做自己的用户

景鲲：产品先服务团队自己，「做自己热爱信任的产品，再推广给大众」。

招人看心态年龄

不看生理年龄，看思想开放度、自我驱动力和行动力；理想人才是兼具行业经验与开放心态的人。

口碑先于广告

早期增长几乎全靠口碑与病毒传播，没有付费投放；2026 年 2 月才第一次买超级碗广告。

护城河在哪里，风险在哪里

投资人和你未来的客户都会问这两个问题。

护城河（公司口径）
  • 执行速度：极小团队加 AI 写代码，发布节奏远快于大公司
  • 分发：企业分销网络、云市场上架、与微软等平台的联合销售
  • 上下文：SecondBrain 积累的个人与团队工作记忆，越用越难迁移
  • 成本工程：多模型路由和高提示缓存命中率
主要风险（学院分析）
  • 模型依赖：核心能力来自 OpenAI、Anthropic、Google，价格和供给受制于人
  • 巨头捆绑：Copilot 与 Gemini 可以用更低价格打包给已有客户
  • 同质化：通用 Agent 的差异在缩小，可能压低高端定价
  • 消费者属性：用户以专业个人用户起步，企业级的留存与扩张仍待验证
  • 隐私：录音硬件和全量工作记忆，在日韩和受监管行业会被重点审视

六条趋势，决定 Genspark 未来两年的形态

每条写清信号、判断与把握程度。判断为学院分析。

模型商品化，价值上移到应用层把握高

信号：景鲲判断两年内同等能力模型的成本将降到现在的 1%；Genspark 已同时调度 70 多个模型。判断：多模型路由和成本工程会成为应用层公司的毛利核心。

从聊天到交付成品把握高

信号：客户按交付物付费（报告、模型、应用），企业版以席位和额度计价。判断：评价 AI 的单位会从「回答质量」变成「省下的工时」。

记忆与上下文成为新壁垒把握较高

信号：SecondBrain、Agent Base、连接器与 MCP 成为 6.0 的主角。判断：谁沉淀了团队的工作记忆，谁就拥有续约；这也会把数据治理推到采购清单最前面。

巨头捆绑与应用层竞合把握中

信号：Genspark 同时是微软的伙伴和 Copilot 的替代品。判断：亚太企业市场会出现「在 Microsoft 365 里买 Genspark」的路径，渠道合作比正面竞争更重要。

数据驻留成为亚太入场券把握中

信号：日本投资计划明确包括为合格客户提供本地数据驻留；企业版提供亚太区域部署。判断：金融、政府客户在日韩之后，会在新加坡、印度、澳洲提出同样要求。

通用 Agent 赛道整合把握中

信号：Manus 被 Meta 收购又被叫停；巨头都在推自己的 Agent。判断：两年内通用 Agent 会剩下少数几家，具备企业分发能力的才能留下。

2028 年的三种情景

用来判断这份工作的上行空间和下行风险。

乐观企业收入占比过半，成为微软、谷歌之外的第三个工作空间选项，亚太是第二大收入区域
基准专业用户和中型企业双轮驱动，年化收入持续增长，被视为通用 Agent 头部公司之一
承压巨头捆绑压低价格，模型成本上升或供给受限，增长转向依赖低价市场
变数被大平台收购或深度绑定，区域团队的独立性随之变化

大中华区：大陆不是选项，台湾、香港是

这与 Dify、Zilliz 等起步于中国的公司截然不同。本节为学院分析，依据公开信息推断。

Genspark 的核心能力建立在 OpenAI、Anthropic、Google 的模型之上，这些模型都不向中国大陆提供服务；公开资料里也找不到它在大陆的业务、团队或计划。现实的「大中华区」只能是台湾、香港和海外华人企业。

中国大陆

判断：不进入。模型供给、数据出境与内容监管三道门槛同时存在；景鲲在 2026 年 8 月的访谈里列出的核心市场也没有中国。例外：跨国公司在华员工可能通过总部合同使用，但这属于全球客户管理，不是区域市场。

台湾

判断：值得做。官网已有繁体中文版本；制造、半导体、电子供应链企业文档与报告密集，英语和日语协作多。打法：通过本地系统集成商和微软渠道，主打报告、提案、供应链文档自动化。

香港

判断：金融与专业服务的入口。投行、律所、咨询公司的交付物（模型、备忘录、路演材料）正是 Genspark 的强项。打法：席位制试点进入，靠合规材料和亚太区域数据部署过关。

台湾、香港的进入路径推演

学院分析，以「不做大陆业务」为前提，不代表公司计划。

  1. 先拿到授权边界：明确台湾、香港由哪个团队覆盖，与日本、新加坡团队如何划分跨国客户
  2. 做繁体中文场景包：把报告、提案、财务模型、投研纪要的模板本地化，作为销售演示的标准件
  3. 选两家伙伴：一家微软生态的系统集成商、一家专业服务或金融科技咨询公司
  4. 打三个标杆：一家金融机构、一家制造或半导体企业、一家专业服务公司，用省下的工时说话
  5. 把合规讲清楚：区域部署、SSO、审计、不训练客户数据，提前准备好给法务与信息安全团队的一页纸
  6. 用数据决定是否加人：以付费席位和扩张率，而不是线索数量，来申请第二批编制

区域团队需要的能力：大客户与伙伴体系、集成商合作、前线部署（FDE）方法论，都能直接用在台湾和香港的金融、制造客户上；同时要补齐产品驱动增长的能力：个人专业用户市场、社区运营与口碑传播。

日韩之外的亚太：按证据强度分级

市场判断为学院分析。景鲲公开列出的核心市场是美国、韩国、日本、法国、印度和巴西。

印度Tier 1 · 规模

信号：被创始人列为核心市场；英语知识工作者和 IT 服务从业者数量巨大。打法：个人专业用户与 IT 服务公司双线，用低单价席位和团队版扩张。

新加坡Tier 1 · 枢纽

信号：亚太区域总部集中地，企业版可在亚太区域部署。打法：以新加坡为东南亚和跨国企业的区域枢纽，主攻金融、咨询与区域总部。

澳洲 · 新西兰Tier 1.5

信号：英语市场，微软生态成熟，专业服务密集。打法：借微软市场与系统集成商，复制北美的企业销售剧本。

台湾 · 香港Tier 1.5

信号：繁体中文官网；金融、制造、专业服务交付物密集。打法：见「大中华区」模块。

东南亚其他国家Tier 2

信号：暂无公开动作。打法：先靠产品自助增长与经销商，达到付费席位门槛再投入人力。

日韩之外的亚太：加速路径推演

学院分析，基于公开信号推演，不代表公司计划。

  1. 厘清边界：日韩之外的市场由谁覆盖，跨国客户由谁负责
  2. 看清数据：各国自然注册、付费转化、团队版扩张率，找出已经在自发增长的市场
  3. 选一个枢纽：新加坡做区域中心，印度做规模市场，各配一个能打的本地负责人
  4. 接住微软：把「在亚洲联合销售」的约定落到具体客户名单和分成规则
  5. 复制日本的伙伴结构：经销商、系统集成商、电信运营商各签一家
  6. 准备数据驻留问答：金融与政府客户的第一道门槛
